Konsep utama

01
PERSIAPAN KOMPUTER15–30 MIN

Siapkan komputer dan hubungkan tool

Target native pertama yang didukung adalah x86_64 + BIOS + GRUB + Multiboot2. Siapkan Python 3.10+, NASM, cross-compiler C/C++ x86_64, linker ELF, tool ISO GRUB, xorriso, dan QEMU.

  • Python 3.10 atau lebih baru
  • Assembler NASM
  • x86_64-elf-gcc dan x86_64-elf-g++
  • x86_64-elf-ld, grub-mkrescue, dan xorriso
  • qemu-system-x86_64
Pada Windows

Jalankan local-agent/start-local-agent.bat. Salin pairing token yang muncul di terminal ke Pengaturan → Lanjutan. Biarkan layanan tetap berjalan selama proses build atau pengujian.

02
PENYIAPAN PROYEK5–10 MIN

Buat proyek kernel pertamamu

Pilih Proyek Baru, lalu tentukan x86_64, BIOS, GRUB, dan C atau C++. Template awal mencakup entry Multiboot2, linker script, source kernel, konsol serial, helper memori, serta modul awal IDT/PMM.

boot/entry.asm boot/grub.cfg include/kernel/ src/kernel.cpp src/serial.cpp src/pmm.cpp src/interrupts.cpp linker.ld kerno.project.json
Mengapa target ini penting

Mengubah metadata arsitektur tidak otomatis mengubah boot assembly, ABI, atau tata letak linker. Jalur native ISO yang saat ini aktif hanya x86_64 + BIOS + GRUB + Multiboot2.

03
ARSITEKTUR BOOT15 MIN

Pahami rantai boot

Pada target BIOS saat ini, firmware memuat GRUB. GRUB mengenali header Multiboot2 lalu memindahkan kontrol ke entry point kernel. Entry stub x86_64 dimulai dalam protected mode 32-bit, memeriksa kemampuan CPU, membuat identity map untuk 1 GiB pertama, mengaktifkan PAE dan long mode, lalu memanggil kernel_main.

BIOS→GRUB→Multiboot2→32-bit entry→Long mode→kernel_main
Informasi yang diberikan GRUB

Multiboot2 menyediakan nilai boot magic dan pointer ke informasi boot. Entry stub Kerno meneruskan nilai tersebut agar kernel dapat membaca memory map dan tag boot lainnya.

04
SOURCE KERNEL20 MIN

Baca berkas source dan tata letak linker

Entry Assembly mengekspor simbol _start. Linker script menempatkan header Multiboot2 di bagian awal citra ELF, lalu mengatur bagian text, data read-only, data writable, dan BSS pada alamat dasar kernel. Kernel bersifat freestanding: kernel tidak dapat mengandalkan runtime sistem operasi atau kode startup standar.

Kompilasi freestanding

Pipeline awal menonaktifkan asumsi lingkungan hosted seperti fungsi memori bawaan, stack protector, PIE, serta exception/RTTI C++. Modul baru tetap harus menyediakan primitive runtime yang dibutuhkannya.

05
SUBSISTEM LOW-LEVEL20–40 MIN

Kenali memori, konsol, dan interrupt

PMM awal menggunakan memory map Multiboot2 untuk mengelola frame fisik 4 KiB di dalam wilayah identity map 1 GiB pertama. Keluaran serial memakai COM1 untuk diagnostik; konsol teks memakai memori teks VGA lama. IDT memasang handler default fail-stop.

Batas implementasi saat ini

Ini adalah fondasi kernel untuk pembelajaran, bukan OS lengkap. Implementasi saat ini belum mencakup heap umum, virtual memory manager lengkap, interrupt controller/PIC/APIC, scheduler, driver, filesystem, atau SMP. Interrupt eksternal masih dinonaktifkan.

06
PEMERIKSAAN SEBELUM BUILD5 MIN

Jalankan pemeriksaan kesehatan toolchain

Buka Pengaturan → Toolchain, lalu jalankan pemindaian lokal. Pastikan NASM, kedua cross-compiler, linker, GRUB, dan xorriso tersedia. QEMU dibutuhkan pada tahap akhir. Target kedua compiler harus menunjukkan triple x86_64.

Jangan lewatkan pemeriksaan ini

Compiler yang ditemukan melalui PATH belum tentu dikonfigurasi untuk target yang benar. Kerno memeriksa target triple compiler sebelum proses kompilasi.

07
CITRA BOOTABLE5–15 MIN

Build dan validasi ISO

Pipeline native berjalan melalui beberapa tahap. Kerno hanya menerima ISO setelah kernel dan citra boot melewati seluruh pemeriksaan yang diwajibkan.

01AssembleNASM → objek ELF64
02CompileC/C++ → objek freestanding
03LinkKernel ELF64 x86_64
04Verifikasi kernelEntry point + Multiboot2
05Siapkan isi ISO/boot/kernel.elf + grub.cfg
06Paketkan ISOgrub-mkrescue + xorriso
07Periksa ISOISO9660 + El Torito + path berkas
08Daftarkan artefakHanya jika semua pemeriksaan wajib lolos
Isi di dalam ISO

Direktori staging menempatkan kernel di /boot/kernel.elf dan menu GRUB di /boot/grub/grub.cfg. Citra harus memiliki volume descriptor ISO9660 yang valid serta katalog boot El Torito untuk BIOS legacy.

08
BOOT PERTAMA5–10 MIN

Jalankan ISO di QEMU dan periksa keluarannya

Setelah verifikasi, jalankan guest QEMU dengan profil BIOS x86_64 yang sesuai. Periksa tampilan VGA dan keluaran serial COM1. Proses QEMU yang tetap terbuka tidak otomatis membuktikan bahwa kernel berhasil dieksekusi.

Saat terjadi kegagalan

Mulai dari laporan kesehatan build, kemudian periksa log proses QEMU dan keluaran serial. ISO yang valid masih dapat berisi kernel dengan kesalahan runtime; validasi citra dan keberhasilan eksekusi guest adalah dua pemeriksaan berbeda.

✓
Tonggak boot kernel pertamamu

Simpan proyek, ekspor arsip source, dan simpan ISO yang telah diverifikasi bersama log build.
